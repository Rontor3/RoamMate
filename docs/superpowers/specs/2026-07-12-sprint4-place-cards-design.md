# Sprint 4 — Place Cards Filtered by Selected Area
**Date:** 2026-07-12
**Scope:** `fetch_place_cards` in `stage_machine.py`, `get_area_reddit_signals` in `reddit_signals.py`, `place_selected` routing, new state fields
**Goal:** Replace the Sprint 4 stub (`show_place_cards, {"places": []}`) with real place cards grouped by dynamic categories, ranked using the existing scorer+ranker, with a background Reddit prefetch that feeds Sprint 5 activity options.

---

## Problem

After a user selects an area (e.g., Vagator, North Goa), the system returns empty place cards. Sprint 4 fills this in: fetch specific venues within that area, group them into dynamic categories (driven by the user's experience type or vibe), rank them using the existing scoring system, and surface them as grouped cards with photos and one-liner hooks.

---

## Context

The system already has:
- **`Ranker`** (`app/services/ranker.py`) — weighted ranking: quality (35%), intent match (25%), crowd fit (20%), authenticity (20%). Weights shift by vibe.
- **`score_all_places`** (`app/services/scorer.py`) — attaches social scores from Reddit + blog signals.
- **`reddit_signals`** and **`blog_signals`** already in state from the discovery node.
- **`search_places(location, query)`** (`app/tools/fetchers/places.py`) — Google Maps MCP returning name, rating, review_count, types/tags, photo_url.
- **`area_cache.py`** — Redis get/set, TTL-based, silent on failure.

What's new in Sprint 4:
- `fetch_place_cards` calls Maps scoped to `{area_name}, {destination}` per category.
- Ranking reuses the existing Ranker (quality + intent match primarily; crowd/auth neutral when no area-level Reddit signals yet).
- A background `asyncio.create_task` fires `get_area_reddit_signals` while the user reads cards — result cached in Redis for Sprint 5's `build_activity_options`.

---

## Branch Flow

Both Branch A (came via experience chips) and Branch B (typed destination → vibes) arrive at `area_selected` stage. Sprint 4 handles both identically — `experience_types` takes priority over `selected_vibe_ids` for the category + ranking context; if both empty, fall back to generic categories.

## 4. `fetch_place_cards` — Core Sprint 4 Feature

```python
async def fetch_place_cards(state: dict) -> list[dict]:
```

**Inputs:** `destination`, `selected_area` (area_id), `experience_types`, `selected_vibe_ids`, `travel_intent`, `reddit_signals`, `blog_signals`

**Cache key:** `f"place_cards:{destination.lower()}:{area_id.lower()}:{exp_key}"`
- `exp_key`: same logic as area cards — sorted experience_types or sorted selected_vibe_ids joined with `|`
- TTL: 43200 (12h)

**On cache hit:** write to `state["place_cards"]`, fire background Reddit prefetch, return cached list.

**On cache miss — 4-step pipeline:**

### Step 1 — Category determination (Groq, max_tokens=250)

One Groq call: given destination, area name, experience_types/vibes, and trip_who/season — determine 3–4 category objects. Each category has a `label` (display name) and a `query` (for the Maps search).

Prompt asks for JSON array:
```json
[
  {"label": "Adventure Spots", "query": "trekking viewpoints cliff adventure"},
  {"label": "Beaches",         "query": "beaches swimming coves"},
  {"label": "Cafés & Bars",    "query": "cafes bars restaurants"},
  {"label": "Heritage",        "query": "forts temples heritage"}
]
```

Always include a food/drink category (`Cafés & Bars` or `Restaurants & Cafés`) regardless of vibe — the spec is explicit that "everyone likes to eat and would like to know venues".

On Groq failure: fall back to `DEFAULT_CATEGORIES` — `[{"label": "Things to Do", "query": "attractions"}, {"label": "Cafés & Bars", "query": "cafes bars restaurants"}, {"label": "Beaches", "query": "beaches"}]`.

### Step 2 — Maps search per category (parallel)

```python
search_tasks = [
    search_places(f"{area_name}, {destination}", cat["query"])
    for cat in categories
]
raw_results = await asyncio.gather(*search_tasks, return_exceptions=True)
```

`area_name` is resolved from `state["area_cards"]` by matching `area_id = state["selected_area"]` → `area["name"]`. If not found, fall back to `area_id`.

Each Maps call returns a list of place dicts with: `name`, `place_id`/`id`, `rating`, `user_ratings_total`/`review_count`, `types`/`tags`, `photo_url`, `lat`, `lng`.

On Maps failure for a category: that category yields `[]` — no crash, just fewer results.

### Step 3 — Score and rank per category

For each category's raw places:
1. **Filter:** rating ≥ 4.2 (consistent with `planning.py`)
2. **Attach social scores:** `score_all_places(places, reddit_signals, blog_signals)` from `app.services.scorer`
3. **Rank:** build `PlaceAreaMapping` objects, call `_ranker.rank_places(mappings, travel_intent, area_scores=None)`
   - `travel_intent` from state (has vibe + interests)
   - `area_scores=None` — area-level signals not available yet (that's what the background Reddit fetch will provide)
   - Quality + intent_match drive ranking; crowd_fit + authenticity default to 0.5 neutral
4. **Take top 3:** `ranked[:3]`

`_ranker = Ranker()` is added as a module-level instance in `stage_machine.py`.

Imports added to `stage_machine.py`:
```python
from app.services.ranker import Ranker
from app.services.scorer import score_all_places
from app.models import Place, PlaceAreaMapping
```

### Step 4 — Hook generation (Groq, one batch call, max_tokens=800)

One Groq call with all places (across all categories) requesting a one-liner hook per place_id:

```json
{"chapora_fort": "Panoramic views of both Vagator beaches — 10-min climb.", "ozran_beach": "Hidden cove below the cliffs, calmer water than main Vagator."}
```

On Groq failure: fall back to `f"A great spot in {area_name}"` per place.

### Assemble and cache

```python
state["place_cards"] = categories_out
await set_cached(cache_key, categories_out, ttl=43200)
```

### Background Reddit prefetch

After assembling (regardless of cache hit or miss):

```python
asyncio.create_task(_prefetch_area_reddit(destination, area_id, area_name, experience_types))
```

Wrapped in try/except — silent if task creation fails.

## 5. `get_area_reddit_signals` — New Function in `reddit_signals.py`

```python
async def get_area_reddit_signals(
    area_name: str,
    destination: str,
    experience_types: list[str],
) -> dict[str, Any]:
```

**Purpose:** Venue-level Reddit signals for a specific area. Deeper comment reading than the destination-level function.

**Queries (up to 4):**
```python
queries = [
    f"{area_name} {destination}",
    f"best places {area_name} {destination}",
    f"{area_name} {destination} {experience_types[0]}" if experience_types else f"{area_name} things to do",
    f"{area_name} {destination} recommend",
]
```

**Comment depth:** 15 comments per post (vs 4 in destination-level), 350 chars each (vs 200). Rationale: venue mentions live in comments, not post bodies.

**Post limit:** 8 posts per query (vs 12 in destination-level) — fewer posts, deeper reading.

Internal call: same `_search_reddit` but with increased `comment_limit` parameter. Add `comment_limit: int = 4` parameter to `_search_reddit` — existing call sites pass no argument, so they default to 4 (no change). Area call passes `comment_limit=15`.

**Returns:** same shape as `get_reddit_place_signals`:
```python
{"place_signals": {...}, "raw_posts_text": "..."}
```

**On failure:** returns `{"place_signals": {}, "raw_posts_text": ""}` silently.

## 6. `_prefetch_area_reddit` — Background Task in `stage_machine.py`

```python
async def _prefetch_area_reddit(
    destination: str,
    area_id: str,
    area_name: str,
    experience_types: list[str],
) -> None:
    """Background task: fetch area-level Reddit signals and cache for Sprint 5."""
    cache_key = f"reddit_area:{destination.lower()}:{area_id.lower()}"
    existing = await get_cached(cache_key)
    if existing:
        return  # already warm
    try:
        signals = await get_area_reddit_signals(area_name, destination, experience_types)
        if signals.get("place_signals"):
            await set_cached(cache_key, [signals], ttl=3600)
    except Exception:
        pass  # background task failure is always silent
```

Cache TTL: 3600s (1h) — Reddit signals are more volatile than place cards.

Sprint 5's `build_activity_options` reads `f"reddit_area:{destination}:{area_id}"` from Redis before doing its own fetch.

## 8. Error Handling

| Failure | Behaviour |
|---------|-----------|
| Groq category determination fails | Use `DEFAULT_CATEGORIES` (3 fixed categories) |
| Maps search fails for a category | That category yields no places; other categories unaffected |
| All Maps searches fail | Return `[]` — frontend shows "couldn't find places, try typing one" |
| Rating filter removes all places in a category | That category is omitted from output |
| Groq hook generation fails | Fall back to `f"A great spot in {area_name}"` per place |
| Redis unavailable | Skip cache read/write; fetch on every request |
| `area_name` not found in `area_cards` | Fall back to `area_id` as the search string |
| Background Reddit task fails | Silent — no crash, no log noise beyond a single warning |
